# Architecture

`src/content/questionBank.generated.json` is the versioned canonical content store. It contains subjects, quizzes, questions, corrected choice text, answer provenance, rationales, embedded reviewed explanations, and review flags. `src/content/questionBank.ts` is its read-only JSON repository adapter: it builds indexes and derives quiz question counts before exposing the `QuizRepository` interface. The explanation catalog selects an embedded reviewed explanation or formats the question's stored rationale; the parser converts the restricted Markdown subset into typed blocks. `src/domain` holds pure quiz rules and types. `src/persistence` implements local storage behind repository interfaces. Completed attempt history is capped at 200 entries, while completion counts plus each quiz's lowest and latest scores are persisted separately so those analytics survive history pruning. Active attempts include an optional stable current-question ID plus persisted accumulated active time and a running-session timestamp, allowing the UI to resume both progress and the stopwatch. Legacy attempts without the timing fields remain compatible through the domain timing helpers. `src/analytics` aggregates structured completed attempts.

`src/app/App.tsx` composes top-level navigation. Its screen components receive data and callbacks, and reusable feedback and quiz components own presentation only. `src/app/session/useQuizSession.ts` coordinates attempt transitions, page-hide pausing, legacy response normalization, and repository writes through the domain and repository interfaces. This keeps screens independent from `localStorage` and leaves room for a future repository implementation.

The runtime never calls a generative AI service. A future API/database repository can implement the existing repository interfaces without changing quiz logic or components; only the JSON adapter knows the present file shape.
