# Architecture

`screenIdentity` in `src/app/navigation.ts` defines stable top-level destinations without including per-question progress or timer updates. `ScreenTransition` in `src/app/components/ScreenTransition.tsx` applies the shared entry animation at the composition boundary in `App.tsx`; the header and global exit dialog remain outside it. Screen content is replaced immediately, and reduced-motion preferences disable the animation.

`ResultsScoreHero` owns the decorative ring and score counter. A single request-animation-frame timeline drives both from the stored result percentage, while `ResultsScreen` remains responsible for the result summary and exact-score celebration.

Dashboard subject summaries live in `src/app/dashboard.ts`. `App.tsx` composes the existing quiz and attempt repositories into those summaries; presentation components receive the resulting data and never read local storage. The active-subject carousel filters and orders only summaries that have saved active attempts, and `embla-carousel-react` owns its responsive scrolling, looping, and drag behavior.

`src/content/questionBank.generated.json` is the versioned canonical content store. Its schema-v4 records use compact type-prefixed IDs (`s*`, `q*`, `i*`) and contain display-ready GFM/KaTeX stems and rationales, canonical choices, answer provenance, and optional rationale metadata such as sources and answer-review notes. The stored shape uses the minimal relationship chain of `question.quizId -> quiz.subjectId`; question order within each quiz is canonical array order. `src/content/schema.ts` defines the storage contract, while `src/content/questionBank.ts` is its read-only JSON repository adapter: it hydrates sparse metadata, builds indexes, and derives quiz question counts before exposing the `QuizRepository` interface. `MarkdownContent` is the sole learner-facing content renderer. Stems and rationales use rich mode: `remark-math` parses math, raw HTML is parsed with `rehype-raw`, the shared restrictive `rehype-sanitize` policy runs before `rehype-katex`, and KaTeX CSS/fonts are bundled locally. `remarkMathPolicy.ts` preserves common currency prose from greedy dollar delimiter pairing. Choices, choice explanations, and sources retain restricted Markdown rendering. `richContentPolicy.ts` owns allowed HTML and image URLs, while `markdownValidation.ts` validates the same math and rich-content rules for canonical and staged content. `src/domain` holds pure quiz rules and types. `src/persistence` implements local storage behind repository interfaces. Completed attempt history is capped at 200 entries, while completion counts plus each quiz's lowest and latest scores are persisted separately so those analytics survive history pruning. A separate per-quiz activity summary records the latest saved or completed use for subject-screen ordering; older browser data falls back to an active attempt's start time or latest completed score. Active attempts include an optional stable current-question ID plus persisted accumulated active time and a running-session timestamp, allowing the UI to resume both progress and the stopwatch. Fast Feedback pauses its persisted timer when all canonical questions have locked answers; resuming a fully answered attempt keeps it paused while the learner reviews. Legacy attempts without the timing fields remain compatible through the domain timing helpers. `src/analytics` aggregates structured completed attempts.

`src/app/App.tsx` composes top-level navigation. Pure selectors in `src/app/progress.ts` build dashboard subject summaries and per-subject quiz progress from repository interfaces and completed attempts, keeping storage reads and analytics out of screens. Its screen components receive data and callbacks, and reusable feedback and quiz components own presentation only. The subject screen owns transient setup-dialog state for a selected new or retaken quiz; setup is not a navigation view. The quiz and answer-browse screens share a responsive question-navigation frame and scroll-to-current primitive while retaining their mode-specific question controls. The answer-browse view is transient navigation state with a quiz and question index only; it reads canonical questions but never creates an attempt or calls the attempt repository, so browsing does not affect activity ordering or analytics. `src/app/session/useQuizSession.ts` coordinates attempt transitions, page-hide pausing, legacy response normalization, and repository writes through the domain and repository interfaces. This keeps screens independent from `localStorage` and leaves room for a future repository implementation.

The runtime never calls a generative AI service. A future API/database repository can implement the existing repository interfaces without changing quiz logic or components; only the JSON adapter knows the present file shape.

`/admin.html` is a separate local-development JSON authoring tool. `useAdminEditor` owns its shared editor state, initial snapshot loading, and unsaved-change warning, while `AdminApp` composes the existing controls and UI actions. The tool does not modify the learner UI, browser attempts, or repository files: it stages change sets in memory, validates the entire schema-v4 bank through the same content checks, and downloads a deterministic replacement bank plus its review change set. Its `AdminQuestionBankGateway` is an asynchronous seam for a later authenticated API; `QuizRepository` remains learner-facing and read-only.
