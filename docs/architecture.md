# Architecture

Dashboard subject summaries live in `src/app/dashboard.ts`. `App.tsx` composes the existing quiz and attempt repositories into those summaries; presentation components receive the resulting data and never read local storage. The active-subject carousel filters and orders only summaries that have saved active attempts, and `embla-carousel-react` owns its responsive scrolling, looping, and drag behavior.

`src/content/questionBank.generated.json` is the versioned canonical content store. Its schema-v4 records use compact type-prefixed IDs (`s*`, `q*`, `i*`) and contain display-ready GitHub Flavored Markdown (GFM) stems and rationales, canonical choices, answer provenance, and optional rationale metadata such as sources and answer-review notes. The stored shape uses the minimal relationship chain of `question.quizId -> quiz.subjectId`; question order within each quiz is canonical array order. `src/content/schema.ts` defines the storage contract, while `src/content/questionBank.ts` is its read-only JSON repository adapter: it hydrates sparse metadata, builds indexes, and derives quiz question counts before exposing the `QuizRepository` interface. `MarkdownContent` is the sole learner-facing Markdown renderer; it uses `react-markdown` and `remark-gfm`, skips raw HTML, and maps semantic Markdown to Material UI. `markdownValidation.ts` parses every canonical Markdown field at validation time and rejects raw HTML, images, and unsafe links. `src/domain` holds pure quiz rules and types. `src/persistence` implements local storage behind repository interfaces. Completed attempt history is capped at 200 entries, while completion counts plus each quiz's lowest and latest scores are persisted separately so those analytics survive history pruning. A separate per-quiz activity summary records the latest saved or completed use for subject-screen ordering; older browser data falls back to an active attempt's start time or latest completed score. Active attempts include an optional stable current-question ID plus persisted accumulated active time and a running-session timestamp, allowing the UI to resume both progress and the stopwatch. Legacy attempts without the timing fields remain compatible through the domain timing helpers. `src/analytics` aggregates structured completed attempts.

`src/app/App.tsx` composes top-level navigation. Its screen components receive data and callbacks, and reusable feedback and quiz components own presentation only. The subject screen owns transient setup-dialog state for a selected new or retaken quiz; setup is not a navigation view. The answer-browse view is transient navigation state with a quiz and question index only; it reads canonical questions but never creates an attempt or calls the attempt repository, so browsing does not affect activity ordering or analytics. `src/app/session/useQuizSession.ts` coordinates attempt transitions, page-hide pausing, legacy response normalization, and repository writes through the domain and repository interfaces. This keeps screens independent from `localStorage` and leaves room for a future repository implementation.

The runtime never calls a generative AI service. A future API/database repository can implement the existing repository interfaces without changing quiz logic or components; only the JSON adapter knows the present file shape.

`/admin.html` is a separate local-development JSON authoring tool. It does not modify the learner UI, browser attempts, or repository files: it stages change sets in memory, validates the entire schema-v4 bank through the same content checks, and downloads a deterministic replacement bank plus its review change set. Its `AdminQuestionBankGateway` is an asynchronous seam for a later authenticated API; `QuizRepository` remains learner-facing and read-only.
