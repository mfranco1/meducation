# Work tracking

Create progress trackers under `docs/work/ongoing` when work begins; create the directory if absent. Record scope, stages, constraints, and relevant verification. For staged work, stop at the agreed stage gate until the user authorizes continuation.

Move completed trackers and their supporting snapshots together into [done](done/) only after implementation and relevant checks pass. Preserve historical claims and frozen machine snapshots. Paths, counts, and results in completed trackers describe the repository at that time; use [current architecture](../architecture.md) and [testing guidance](../testing.md) for present rules.
