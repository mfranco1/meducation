# Work tracking

Use one concise tracker under `docs/work/ongoing` for sustained work. Record scope, decisions, remaining work, and actual checks/results. Routine edits do not require a tracker or separate JSON evidence; add supporting snapshots only when they establish a necessary contract or acceptance result. For staged work, stop at the agreed stage gate until the user authorizes continuation.

Move completed trackers and their supporting snapshots together into [done](done/) only after implementation and relevant checks pass. Preserve historical claims and frozen machine snapshots. Paths, counts, and results in completed trackers describe the repository at that time; use [current architecture](../architecture.md) and [testing guidance](../testing.md) for present rules.
