# L0-A — Progress backup browser acceptance

Status: acceptance criteria selected 2026-10-13; production backup implementation and acceptance runs pending L1. Owner: [L1 progress backups](L1-progress-backup-plan.md). Contract: [progress backup ADR, Step 6](../../decisions/0002-progress-backup-and-restore.md). This checklist remains ongoing until application evidence and required launch checks are recorded.

## Evidence and execution rules

Use synthetic fixture progress in isolated browser contexts; never inspect personal progress or copy it to logs/screenshots. Desktop automated targets: maintained Chromium, Firefox and WebKit, production learner bundle, secure origin (plus loopback development). Record actual browser/OS/version, command, origin/mode, test IDs/results and evidence path. Prefer deterministic injected storage faults for exhaustive recovery; supplement with real storage exceptions/quota. Private browsing does not always block storage: verify actual behavior rather than assuming it does.

Existing evidence is limited: [Step 3](../done/L0-step3-coordination-evidence.json) has 21 isolated Chromium/WebKit passes; Firefox launch unavailable; real BFCache return unobserved. [Step 4](../done/L0-step4-restore-evidence.json) is an in-memory interruption model. [Step 5](../done/L0-step5-limits-evidence.json) is synthetic sizing/invariants. None is a completed application test below. Existing learner CI is Chromium only. Manual iOS/Android and assistive-technology checks must be run against the implemented utility before public launch.

## Required application cases — all pending

- [ ] **B01 — Supported admission and round trip.** On each desktop engine, initialize shared participation before any progress read/write. Export empty/populated paired progress under exclusivity, then replace and reload. Assert exact selected fields/durable totals, fresh revisions, paused timers, no mixed snapshots and no journal after verified cleanup. Downloaded file passes its own importer.
- [ ] **B02 — Missing/rejected capabilities.** Remove Web Locks before app initialization and separately reject actual lock acquisition; test an insecure non-loopback origin where feasible. Deny storage reads and separately writes. Assert specific guidance, exact byte preservation, no persistent study/pagehide writes without participation, no normal uncoordinated export/restore and no fake empty success. Readable absent journal plus exclusive access may allow read-only export when writes fail. Missing file/download APIs disable the affected action only; study with otherwise valid admission remains available.
- [ ] **B03 — Journal admission and recovery.** Boot with prepared/committed/malformed/oversized/conflicting journals and absent/corrupt originals. Assert no partial snapshots or study writes; original/imported decisions select the correct exact pair. Recovery twice is idempotent. Missing coordination/inaccessible storage fails closed. Raw recovery preserves readable strings/nulls, rejects failed reads/oversize, and is clearly non-importable; capture without exclusivity is labelled potentially inconsistent.
- [ ] **B04 — Multi-tab interleavings.** Use separate same-origin pages sharing storage. Test paired export blocked by a shared owner, restore blocked by a shared owner, two competing restorers, two recovery starters, and a new reader during exclusive work. No forced lock, half-restored reads or cooperative writes during exclusivity. Blocked attempts can cancel/rejoin/retry without deadlock. Preview base mismatch forces re-preview. Include legacy writer bypass as documented limitation, not a passing fencing guarantee.
- [ ] **B05 — Lifecycle and lease loss.** Save quiz synchronously before pagehide lease release. Exercise reload, close/crash, hidden/frozen owner, lock loss and back/forward. Hidden owners may safely block. On actual persisted-pageshow return, discard stale sessions and re-enter admission before writes; fresh-load path must also be safe. Record actual navigation result and browser settings; synthetic event injection alone does not close real-return coverage. Test controlled reload without a reload loop or duplicate completion.
- [ ] **B06 — Storage interruptions and quota.** Inject before/after faults at every storage call, including write-success/read-failure decision uncertainty, rollback, target readback and cleanup. Confirm exact decision-selected pair after restart or retained journal plus gate; no fabricated success or discarded raw bytes. Exercise actual quota exhaustion in a disposable origin on desktop engines and actual private-mode behavior. Tiny admission probes do not imply sufficient restore space. Never evict progress to fit a journal.
- [ ] **B07 — File input lifecycle.** Cancel picker from idle and with a valid preview; preserve prior preview on picker cancellation. Select the same file twice, including after invalid input; clearing input permits a second change. Cancel dialog while File.text is pending; its late result does not reopen/repopulate/commit. MIME/extension do not bypass format validation. No writes before confirmation.
- [ ] **B08 — Strict bounded validation.** Run L1 codec adversarial fixtures and browser too-large files. Check File.size before reading, UTF-8 output cap, bounded tree traversal and schema/semantic ceilings. Reject unsupported versions, raw recovery/local-storage dumps, dangerous keys and invalid totals with safe errors/zero writes. Preview/render never inserts imported HTML or logs raw content. Valid unknown content IDs work without a loaded bank.
- [ ] **B09 — Study/review/results navigation.** Active quiz and flashcard utilities are disabled with discoverable save-and-leave instructions. Review uses existing exit confirmation before opening; cancel preserves review. Cancel pending delayed launches before opening. Results/browse cancellation preserves the screen; successful restore clears all feature sessions/callbacks and focuses Quizzes dashboard. Empty replacement has explicit warning.
- [ ] **B10 — Keyboard, focus and announcements.** Tab/Shift-Tab stay in labelled dialog; opening/closing/success focus destinations are meaningful and stable. Escape/backdrop cancel before writes without mutation, including during reading. During committing/recovery mutation they cannot dismiss; duplicate clicks cannot restart. Assert accessible names, busy state, polite status/blocking alert, discoverable disabled-action explanation and retry/cancel guidance. No misleading cancellable state after mutation starts.
- [ ] **B11 — Small screen and preferences.** At 390px, enlarged text and reduced motion, preview/error/confirmation/recovery content scrolls and all actions remain reachable; no page-wide horizontal overflow. Status/error meaning does not depend on color or animation. Check long safe error copy and empty/near-limit backup summaries.
- [ ] **B12 — Network, memory and download resources.** With content API failing/offline, backup validation/restore still work on an already loaded app. Observe fetch/XHR/beacon/forms: no backup bytes, filenames, progress summaries or operation telemetry leave the browser. Existing unrelated content requests are allowed. Verify safe app-generated filename, Blob initiation before revocation, eventual URL cleanup, preview disposal and stale callback invalidation on close/replace/unmount. Browser download initiation is not proof of off-device saving.
- [ ] **B13 — Real mobile files and navigation (public-launch gate).** On actual maintained iOS Safari and Android Chrome, record OS/browser/version. Download to user-accessible files, select it again, transfer/import, cancel/reselect, background/return and back/forward safely. Check 390px-equivalent layout/focus, timer pause and unavailable/quota copy. Headless WebKit/mobile emulation does not replace this check. Retain observed BFCache/fresh-load path.
- [ ] **B14 — Assistive technology (public-launch gate).** Keyboard plus actual VoiceOver/Safari or NVDA/Firefox or Chrome: labelled entry/dialog, disabled study guidance, replacement warning, preview counts, reading/commit/error/success announcements, focus trap/return and recovery actions. No announcement flooding or inaccessible busy state. Record platform/browser/reader versions and result; automated accessibility attributes alone do not close this gate.

## Completion and release rules

L0-A design is complete once criteria/protocol/limits are selected. B01–B12 are L1 feature-completion gates; real BFCache observations must explicitly distinguish observed returns from safe fresh loads and outstanding unobserved paths. B13–B14 and real mobile/Safari lifecycle observations are public-launch gates. A protocol violation requires design repair and rerunning affected tests. A missing browser run stays pending; it cannot be silently counted as passing or replaced by a model. Any narrowed browser support must be explicitly recorded in the ADR/product copy and safely disable affected persistence/backup actions.

Record completed results here during L1. Move this tracker to docs/work/done only after all required feature/launch gates have evidence; the parent L0 tracker remains ongoing for Steps 7–9.
