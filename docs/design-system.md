# Design system

This document owns visual and interaction conventions. Use the existing MUI theme, readable question/explanation layouts, semantic lists, responsive spacing, and visible keyboard focus. Preserve canonical wording and meaningful formatting when changing presentation. [Product behavior](product.md) defines quiz modes and save/abort semantics; [architecture](architecture.md) defines implementation boundaries; [content management](content-management.md) and [testing](testing.md) define review and verification requirements.

In the local admin, omit subtitles that repeat the heading, picker, or obvious next action. Keep empty-content and no-results messages, result counts, validation and stale-preview feedback, and concise destination context because they report actual state. Let navigator cards fit their controls and content; only long record lists receive a bounded scrolling region. Label JSON editors **JSON** and keep outlined labels fully visible above their border, including for multiline fields.

Admin panels use the shared responsive sizing rules in `src/admin/components/adminPanelLayout.ts`: stacked navigators, editors, and status cards fill the available width; at `lg`, navigators/status keep their width and the editor fills the remaining space. Start alignment controls height, so it must never be relied on to provide horizontal stretching. Deletion reviews initially focus Cancel, reject stale content, and disable confirmation during staging. Selection mode stays within the current parent and search, keeps selection across pages, and clears removed records.

### Brand identity

Use `src/shared/brand.ts` as the canonical Meducation identity and `src/shared/ui/brand/AppBrand.tsx` or `BrandMark.tsx` for every wordmark or open-book mark. The mark uses mirrored flat page shapes and detached rounded rails; its small optical form thickens the rails and opens the spine. Do not recreate it with an icon package or duplicate the wordmark in a header. `AppBrand` supports `full`, `icon`, and `wordmark` variants, horizontal or stacked full layouts, responsive artwork widths, a root CSS class, light/dark themes, and full-color, inherited monochrome, black, or white color modes. The light logo palette is burnt orange `#C45117`, apricot `#EF9B6B`, and charcoal `#262626`; dark surfaces use `#EF9B6B`, `#FFC39E`, and white. Keep `#b9511b` for the application action accent. The wordmark uses the existing app font stack, weight 800, and `-.04em` tracking. At icon widths of 20px or less, select the optical small geometry. Static uses expose one accessible Meducation image name; decorative uses set `decorative`, and clickable uses keep an explicit action label and navigation callback at the call site. The Vite branding plugin supplies page titles, theme color, and a square 16px-ready favicon with light/dark system-color support from this same identity for both HTML entries. SVG wordmark text uses the existing font stack; applications that export it outside the app should convert text to paths when their print workflow requires a font-independent file.

The local flashcard admin navigator scopes cards to one selected subject and deck. Keep the pickers and context actions visible above a bounded, independently scrolling card list; search the selected deck and paginate results in canonical order, 25 per page. Keep the editor draft while searching or changing pages. Changing subject/deck goes through the existing draft-discard guard. At narrow widths, bound the navigator height and let it stack above the editor without horizontal overflow.

### Empty states

For a simple empty page or catalog result, let the parent surface show through: use a transparent, borderless layout rather than another card or panel. Center one concise heading and the regular Meducation icon inside a single pale accent circle, with the content group optically offset about 12px below the mathematical center. Do not put a white tile behind the logo, layer decorative card illustrations around it, or repeat the reason in a subtitle when the heading and surrounding filter already explain the state. Add one clear action only when it resolves the empty state, such as returning from an empty filter to All. Keep the brand mark decorative when the heading communicates the state, preserve visible focus on actions, and announce changed empty content politely. Apply this pattern to learner catalog empty states by default, including quiz and flashcard subject screens after their catalog has loaded successfully; keep each screen's existing minimum height and responsive padding, and avoid adding a second card or outer list gap. Use a richer recovery or explanation when the user needs that information to proceed.

### Admin presentation

The `/admin.html` authoring tool reuses the shared warm theme. Panels and preview surfaces use the theme's 14px corners; interactive rows use 10px corners. Primary authoring and export actions use the primary accent, while routine destination/workspace context uses neutral text. Green, red, and warning tones are reserved for success, errors, and warnings. Retain semantic validation feedback, record identities, preview review evidence, meaningful empty states, and accessible labels/focus. The compact Content admin header groups utilities under More and session controls under Account. Workspace status opens details for unsaved quiz/flashcard text and the saved draft versus publication. Review & publish opens a focused dialog; a visible explanation accompanies blocked publication. Export content offers explicit paired saved-draft, current-publication, and selected-publication targets. Published versions loads on demand and keeps activation separate from export. Review save prepares server impact; Save draft is reserved for the final confirmation. Save/history/discard review dialogs initially focus the cancellation action and use full-screen presentation on narrow displays. Expand capped affected-ID groups with a Showing N of M disclosure rather than implying a full diff. Detailed content field requirements belong in content management documentation rather than repeated subtitles in the editor.

Admin browsing selects one subject, then one quiz or deck, before showing its items. Search the selected quiz by full stem and stable ID; search a selected deck by front, back, or ID. Item/card lists show 25 records per page in canonical order, with bounded independent scrolling and range/total controls. Keep pickers, context actions, search, and pagination outside the list scroll area. Use named Add, parent/record actions, and Workspace menus to group less frequent actions; keep Save draft near the editor and paired Undo/export in the labelled More menu. Parent deletion opens one review dialog with the full descendant counts, affected-record paging, a reason, and a Review deletion action before final server save review. Subject deletion stages quiz and flashcard cascades together; one Undo restores both banks. Export remains a local download.

Active quizzes, Browse Answers, results review, and flashcard study use shared bounded Left/Right navigation. Arrow shortcuts pause for open drawers and dialogs and preserve native behavior in answer radios, editable controls, links, and arrow-operated widgets. Advancing from a focused Next/Continue button to the final item moves focus to its terminal action.

The learner uses a warm, fixed left navigation rail with a 240px expanded width and 64px collapsed width. The Meducation brand sits first, followed by the Quizzes/Flashcards destinations. A faint partial horizontal divider sits halfway between the brand and first destination. A small left/right arrow toggle is centered vertically on the drawer's right edge; its arrow appears while the pointer is over the drawer or toggle, or when keyboard focus reaches the toggle. On devices without hover, keep the arrow visible for touch discovery. The full drawer edge shares its hit target and shows a subtle orange line on hover or keyboard focus. Brand and destination buttons use a consistent 10px corner radius and do not change their background on hover; the edge toggle has no ripple or hover fill. Fixed-height brand and spacer slots keep destinations vertically aligned as the rail collapses. Expanded navigation shows labels; collapsed navigation keeps accessible names and tooltips with icons only. At narrow widths, the rail remains reserved and expansion opens a labelled overlay drawer. The selected section has a warm accent surface; `aria-current` is reserved for the actual Quizzes or Flashcards dashboard. Drawer and arrow transitions honor reduced motion. The navigation stays available while the main screen loads.

Progress backup is a labelled MUI utility dialog with a scrollable body and reachable footer actions. Keep separate preview counts, replacement warnings, polite reading status, dialog busy semantics and alert errors. Before commit, Escape and Cancel preserve stored progress; during commit/recovery they cannot dismiss. Closing returns focus to the entry action; verified restoration announces success and focuses the Quizzes dashboard after reload. Disabled study/file actions need discoverable guidance. Preserve keyboard access at narrow widths, enlarged text and reduced motion. See [backup behavior and recovery](progress-backup.md).

Reusable toasts use MUI semantic severity colors and iconography, stack by configurable viewport position, wrap within the viewport, and render in a body portal above page content and below modal dialogs. Their border and shadow are restrained. They fade in over 180ms and fade out over 140ms without moving; reduced-motion preference removes these transitions. Informational toasts expire after a configurable TTL by default; persistent notifications use a null TTL and manual dismissal. Toast scope can be global or tied to a screen identity. A persistent error toast uses alert semantics, stays at the bottom right, and has a keyboard accessible close button.

Quiz, Browse Answers, and results review use the same question-count/progress hierarchy, responsive question navigator, compact answer-row geometry, and right-aligned Previous/Next footer. The terminal Finish/Submit action in the shared study footer uses the theme's primary color, matching quiz submission controls; it is an action control, not success feedback. Keep this color fixed in the shared footer. Reserve semantic success green for correctness feedback and outcomes. Browse and Review render radio-style answer indicators as decoration without creating input controls. Review marks the submitted selection with a checked radio indicator and highlights the revealed correct answer with a green surface and green radio indicator, a static final time in the stopwatch position, and a noninteractive submitted flag. The shared feedback panel uses semantic status tones and readable explanation content; unavailable keys and missing explanations need explicit text. Selection and correct-answer labels remain available to screen readers without visible text beside the choice. Active quizzes also use green radio indicators when a correct answer is revealed. Quiz and review navigator filters use the same joined segmented pill. The active quiz screen remains the visual reference for these read-only modes.

Flashcard study shares the quiz count/progress header and right-aligned navigation footer, without a stopwatch. Its white card centers the front prompt and keeps the flag control in a separate corner. The answer panel alone flips; its faces use a theme-neutral paper rim, a primary-orange field with inward-curved corners, and one white inset outline. Derive the outline inset as 28.125% of the orange field's outer margin, then derive its corner radius in CSS as `calc(outer frame radius + outline inset)` because concave cutouts require a larger concentric arc. Keep the arc centers at the original orange-field corners; intersect the expanded circles with the inset straight edges to keep the gap uniform at mobile and desktop sizes. Use a 1.5px white stroke for clear contrast while retaining a fine printed look. A restrained, soft layered shadow suggests paper thickness without a hard bottom edge. Hover raises the answer card by 3px on fine pointers. A 1200px perspective supports its 420ms Y-axis flip; reduced motion removes perspective and transitions. Both faces share the intrinsic height of the answer content so text stays within the panel through the flip. Revealed answer text is bold and centered; clicking the answer panel hides it, while links remain interactive. Space reveals a hidden answer and advances from a revealed card to the next card; the brand-orange card focus outline stays suppressed during this Space-driven focus flow and returns when the learner tabs or moves focus away. Left and Right Arrow navigate to the previous and next card, including when an ordinary button has focus; editable controls, links, arrow-operated widgets, and an open Cards drawer or dialog retain their keyboard behavior. Arrow navigation stops at deck boundaries, keeps the destination answer concealed, and leaves Finish explicit. The card navigator reuses the quiz orange answered tile treatment for opened cards, with its own All/Hidden/Flagged filters. The flip honors reduced motion and never wraps rich interactive answer content in a button.

Flashcard subject deck cards use the quiz subject card's small outlined completion pill, labelled `Completed 1 time` or `Completed N times`, only after a recorded finish. It sits below the deck card count in a wrapping row with the outlined saved-position pill, so both remain readable on narrow screens.

Top-level screen entry uses a shared 170ms fade with a 6px upward settle and `cubic-bezier(0.2, 0, 0, 1)` easing. The header remains stationary and screen content stays interactive. Reduced-motion preference disables this transition. In-screen updates, including quiz question changes, are immediate; dashboard catalog pagination is the exception and slides the grid horizontally while leaving its heading and footer stationary.

When a lazy top-level screen or app startup must wait, keep the Meducation header visible and center an 80px mobile / 96px larger-screen Meducation icon, a rounded 208px mobile / 240px larger-screen indeterminate bar that is 6px tall, and one centered 1rem mobile / 1.125rem larger-screen status line in that order in the remaining content area. The off-white shell fills the viewport below its header; pending main content is marked busy and the status is announced politely. Resolve directly to content, with a 170ms opacity fade only when a loading fallback was displayed and the existing screen-entry animation has ended. Reduced motion shows a static bar and disables the fade. Catalog skeletons and inline question progress keep their existing presentations.

The Results hero presents “Quiz complete” and the score inside a hollow circular ring. Its gray track uses `grey[300]`; its clockwise arc starts at 12 o’clock and uses the score color from `theme.palette.scoreRing`. The 100-unit SVG uses a 47-unit radius and 4-unit stroke. One elapsed-time animation drives the arc, integer counter, and color together. A two-part Hermite curve advances about 85% of the score in the first 65% of the timeline, then eases continuously to the final value. Duration scales from about 535ms at 1% to 1,300ms at 100%. The stroke blends smoothly from red through yellow and light green to green around 58–63%, 73–78%, and 88–93%. These colors are decorative cues; the numeric result remains authoritative. Zero has no arc, and invalid percentages safely display zero. The final score remains available as stable screen-reader text while changing visual digits are hidden from announcements. Reduced-motion preference shows the final number, ring, and color immediately.

The quiz and flashcard dashboards share the same responsive dashboard frame, subject grid, subject-card base, and user-controlled study carousel. All Subjects cards use one column on narrow screens, two at intermediate widths, and three on desktop; show at most 12 cards per page in catalog order. The footer uses Previous/Next text buttons matching study navigation and a page count, including for one nonempty page. A short, borderless joined All/In progress pill sits to the right of the All Subjects heading; its selected option uses primary orange with white text. It filters only that grid, resets pagination, and shows a clear empty state. Keep catalog empty states transparent and borderless so they sit on the dashboard surface without reading as another card. Center the regular Meducation mark directly inside one pale circle; do not put it on a white tile or add a second decorative illustration. Use one concise heading, omit a subtitle when it repeats the heading or filter context, and keep only a useful recovery/filter action such as Show all subjects when the active filter has no matches. Reuse these rules for empty catalog pages and other simple empty states unless their task needs an action or status explanation. Page changes slide horizontally in the direction of navigation; filter/data resets settle immediately, and reduced motion replaces pages without animation. The controls stay unavailable while catalog/activity data is loading or unavailable.

All Subjects grid cards opt into the catalog card's dashboard appearance: a decorative subject-ID icon in a pale circular badge sits beside the full title. Use a 1.25rem title and a larger 1.75rem icon consistently, keep the badge footprint fixed, and center the title vertically against the icon even when it wraps. Do not scale titles individually or truncate them. Quiz cards show latest score and the existing accessible trend indicator in a fixed metadata row above the static rounded score track; any in-progress count shares that row, including when no score is available. The visible score text is the accessible equivalent of the track; the track itself is decorative, has no progressbar role, and does not animate. A missing score uses an empty track without displaying zero. Flashcard grids share the icon/header and card appearance, but have no score track; show active deck counts in a reserved footer without implying a score or completion percentage. The icon registry maps stable subject IDs to reusable MUI icons or local SVG components under src/shared/ui/catalog/icons; unknown IDs use the grid icon. Continue Studying uses shared `ContinueStudyCard` and `StudyCardIllustration` presentation on both dashboards. Each card has a cream surface, full subject title, singular/plural activity count, orange Continue action, and decorative SVG artwork composed with the stable subject icon. The entire card is one labelled button; its CTA is a visual span inside that button. Continue opens the subject, where the learner chooses or resumes a quiz/deck. The section heading stays available to assistive technology without taking visual space. The carousel never auto-advances, uses labelled previous/next controls with wraparound navigation, and shows controls only when more than one snap is reachable. Continue Studying displays exactly one full card at all available widths; additional cards are reached with carousel controls. Standard carousel consumers retain their existing sizing. Subject cards use native button semantics and visible focus treatment; reduced-motion navigation jumps directly to the next item. Quiz and flashcard subject pages share the same back/header frame while keeping feature-specific lists and actions separate.

Both dashboards use the shared catalog `StatCard` and `StatCardRow` for a warm, softly orange-shaded summary row. Cards use the theme's 14px radius and place a decorative orange outline icon beside a compact label, a large left-aligned value, and a short supporting unit below. Keep equal card widths at tablet/desktop sizes and stack them on narrow screens; values and supporting text may wrap without clipping. Icons are decorative and cards are not interactive. The lowest quiz subject appears as the accent-colored supporting line. Flashcard cards use concise **Completed**, **Average**, and **Highest** labels, with supporting units **decks**, **decks / day**, and **decks finished in a day**; omit unnecessary decimal zeros in the average. Keep loading and unavailable values distinct from zero. Progress read errors show unavailable values instead of zero. Keep locally stored stats visible while the subject catalog loads or recovers. Quiz results continue using the results variant's existing compact presentation.

The MUI theme owns semantic feedback tones for correct, incorrect, and answer-under-review surfaces, borders, and separators. Quiz choices, the feedback header, and Browse Answers use these tokens so a palette adjustment stays consistent without changing the written correctness and review signals. The pearl surface uses `primary.light`.

Meducation uses a light, warm autumn palette with `#b9511b` as its restrained primary accent, off-white surfaces, strong type hierarchy, soft borders, 14px radius cards, and visible native MUI focus states. Correctness always combines written feedback, an icon, and color. Immediate feedback uses a compact tinted status header followed by a neutral reading surface; long explanations should have a clear heading, generous line height, and a constrained readable measure rather than a fully tinted wall of text. The shared rich-content renderer presents canonical stems and rationales as semantic Markdown, sanitized HTML, images, and KaTeX math. Inline equations align with text; display math has readable spacing and long expressions scroll within their own bounded area on narrow screens. Math fonts load locally. Tables also scroll horizontally on narrow screens, and images use meaningful alt text, lazy loading, their natural aspect ratio, and a responsive bounded width. The highlighted answer choices communicate which selection was correct or incorrect, so do not repeat answer summaries in feedback. Render optional high-yield pearls as separate callouts. A correct-answer choice receives a short, local green-circle burst, while centered celebration overlays remain reserved for streak and perfect-test events. Both effects are decorative, pointer-transparent, and non-blocking: they do not move focus, obscure controls, or shift layout. They honor `prefers-reduced-motion` by omitting moving circles while preserving written and static correctness signals. Visual formatting must not change canonical Markdown semantics.

For dashboard and subject catalogs, use MUI wave skeletons that match card and score dimensions to reserve layout space. Use restrained warm shimmer contrast and disable animation when the user prefers reduced motion. Keep headings, navigation, and locally available statistics visible while content loads. Quiz catalogs and flashcard subject catalogs share the same warm, full-width recovery banner immediately below the header, with a bordered Retry control. Their dependent cards, grid, or four subject rows retain the warm shimmer skeleton shape. Loading a selected flashcard deck uses the orange indeterminate progress bar at the shell top, as for quiz question loading, while its deck rows stay visible and its selected action is disabled. A failed deck launch uses the existing persistent bottom-right error toast; Study/Resume remains available for another try. An independent dashboard failure stays in the affected card or subject grid, with a small note and outlined Retry button. Mark loading sections `aria-busy`, give each section an accessible loading label, and keep placeholders out of the focus order. Map internal errors to learner-safe copy; technical status codes and raw exceptions belong in developer logs only. Do not show zero or empty states until that resource has loaded successfully.

In-app admin navigation and batch closing use a shared **Discard unsaved edits?** dialog with **Keep editing** as the initial focus. Escape and Keep editing retain exact text. Text/context changes invalidate the captured decision. Browser unload protection retains the native browser prompt. Explicitly canceled save reviews use neutral editing feedback; validation and request failures retain error feedback. Flashcard records and batches expose an editable, required Change reason; changing it invalidates the prepared review.


Admin content uses Quizzes/Flashcards tabs with unsaved indicators. Both sections pair a 320px desktop navigator with a flexible editor and stack at narrow widths. Use explicit Add quizzes/questions/decks/cards actions and labelled Subject/Quiz/Deck actions menus. Manage subjects opens a shared dialog without switching sections. An unselected editor shows the next context choice and an applicable add action; do not render a blank JSON area and disabled save control. Selected editors use a stable footer for unsaved/saved status and review/save actions. Quiz validation and selectable technical diagnostics live in an expandable region inside the editor rather than a third desktop column.

Both batch workflows show Content → Review → Save draft, destination context, and the 10,000-new-record limit before reservation. Label flashcard compiler IDs as provisional and quiz server-preview IDs as reserved. Flashcard batch and shared-subject dialogs use full-screen narrow layouts. Single records use Edit / Preview / JSON views, defaulting to structured source fields. IDs and relationships are read-only in forms; existing source answers remain separate from verified answers. Optional fields have explicit presence controls, and choice reordering uses labelled actions without relabelling IDs. Invalid or unsupported form shapes remain exact editable JSON. View switching must not dirty a record. Preview uses the shared rich/restricted renderer. Batch composition retains content-only JSON and all existing batch capabilities.
