# Design system

This document owns visual and interaction conventions. Use the existing MUI theme, readable question/explanation layouts, semantic lists, responsive spacing, and visible keyboard focus. Preserve canonical wording and meaningful formatting when changing presentation. [Product behavior](product.md) defines quiz modes and save/abort semantics; [architecture](architecture.md) defines implementation boundaries; [content management](content-management.md) and [testing](testing.md) define review and verification requirements.

The local flashcard admin navigator scopes cards to one selected subject and deck. Keep the pickers and context actions visible above a bounded, independently scrolling card list; search the selected deck and paginate results in canonical order, 25 per page. Keep the editor draft while searching or changing pages. Changing subject/deck goes through the existing draft-discard guard. At narrow widths, bound the navigator height and let it stack above the editor without horizontal overflow.

### Admin presentation

The `/admin.html` authoring tool reuses the shared warm theme. Panels and preview surfaces use the theme's 14px corners; interactive rows use 10px corners. Primary authoring and export actions use the primary accent, while routine destination/workspace context uses neutral text. Green, red, and warning tones are reserved for success, errors, and warnings. Retain semantic validation feedback, record identities, preview review evidence, meaningful empty states, and accessible labels/focus. Keep the quiz export explicit in the shared header and flashcard export in its authoring section. Detailed content field requirements and file replacement guidance belong in content management documentation rather than repeated subtitles in the editor.

Active quizzes, Browse Answers, results review, and flashcard study use shared bounded Left/Right navigation. Arrow shortcuts pause for open drawers and dialogs and preserve native behavior in answer radios, editable controls, links, and arrow-operated widgets. Advancing from a focused Next/Continue button to the final item moves focus to its terminal action.

The learner uses a warm, fixed left navigation rail with a 240px expanded width and 64px collapsed width. The Meducation brand sits first, followed by the Quizzes/Flashcards destinations. A faint partial horizontal divider sits halfway between the brand and first destination, aligned with the arrow toggle. A small left/right arrow toggle is anchored to the right edge at the old toggle's vertical position; the full drawer edge shares its hit target and shows a subtle orange line on hover or keyboard focus. Brand and destination buttons use a consistent 10px corner radius and do not change their background on hover; the edge toggle has no ripple or hover fill. Fixed-height brand and spacer slots keep destinations vertically aligned as the rail collapses. Expanded navigation shows labels; collapsed navigation keeps accessible names and tooltips with icons only. At narrow widths, the rail remains reserved and expansion opens a labelled overlay drawer. The selected section has a warm accent surface; `aria-current` is reserved for the actual Quizzes or Flashcards dashboard. Drawer and arrow transitions honor reduced motion. The navigation stays available while the main screen loads.

Reusable toasts use MUI semantic severity colors and iconography, stack by configurable viewport position, wrap within the viewport, and render in a body portal above page content and below modal dialogs. Their border and shadow are restrained. They fade in over 180ms and fade out over 140ms without moving; reduced-motion preference removes these transitions. Informational toasts expire after a configurable TTL by default; persistent notifications use a null TTL and manual dismissal. Toast scope can be global or tied to a screen identity. A persistent error toast uses alert semantics, stays at the bottom right, and has a keyboard accessible close button.

Quiz, Browse Answers, and results review use the same question-count/progress hierarchy, responsive question navigator, compact answer-row geometry, and right-aligned Previous/Next footer. The terminal Finish/Submit action in the shared study footer uses the theme's primary color, matching quiz submission controls; it is an action control, not success feedback. Keep this color fixed in the shared footer. Reserve semantic success green for correctness feedback and outcomes. Browse and Review render radio-style answer indicators as decoration without creating input controls. Review marks the submitted selection with a checked radio indicator and highlights the revealed correct answer with a green surface and green radio indicator, a static final time in the stopwatch position, and a noninteractive submitted flag. The shared feedback panel uses semantic status tones and readable explanation content; unavailable keys and missing explanations need explicit text. Selection and correct-answer labels remain available to screen readers without visible text beside the choice. Active quizzes also use green radio indicators when a correct answer is revealed. Quiz and review navigator filters use the same joined segmented pill. The active quiz screen remains the visual reference for these read-only modes.

Flashcard study shares the quiz count/progress header and right-aligned navigation footer, without a stopwatch. Its white card centers the front prompt and keeps the flag control in a separate corner. The answer panel alone flips; it uses the primary orange surface, matching card corner radius, and a large centered icon-only Meducation logo while concealed. Both faces share the intrinsic height of the answer content so text stays within the panel through the flip. Revealed answer text is bold and centered; clicking the answer panel hides it, while links remain interactive. Space reveals a hidden answer and advances from a revealed card to the next card. Left and Right Arrow navigate to the previous and next card, including when an ordinary button has focus; editable controls, links, arrow-operated widgets, and an open Cards drawer or dialog retain their keyboard behavior. Arrow navigation stops at deck boundaries, keeps the destination answer concealed, and leaves Finish explicit. The card navigator reuses the quiz orange answered tile treatment for opened cards, with its own All/Hidden/Flagged filters. The flip honors reduced motion and never wraps rich interactive answer content in a button.

Flashcard subject deck cards use the quiz subject card's small outlined completion pill, labelled `Completed 1 time` or `Completed N times`, only after a recorded finish. It sits below the deck card count in a wrapping row with the outlined saved-position pill, so both remain readable on narrow screens.

Top-level screen entry uses a shared 170ms fade with a 6px upward settle and `cubic-bezier(0.2, 0, 0, 1)` easing. The header remains stationary and screen content stays interactive. Reduced-motion preference disables this transition. In-screen updates, including quiz question changes, are immediate.

When a lazy top-level screen or app startup must wait, keep the Meducation header visible and center a 32px warm-accent progress ring with one short muted status line in the remaining content area. The off-white shell fills the viewport below its header; pending main content is marked busy and the status is announced politely. Resolve directly to content, with a 170ms opacity fade only when a loading fallback was displayed and the existing screen-entry animation has ended. Reduced motion shows a static ring and disables the fade. Catalog skeletons and inline question progress keep their existing presentations.

The Results hero presents “Quiz complete” and the score inside a hollow circular ring. Its gray track uses `grey[300]`; its clockwise arc starts at 12 o’clock and uses the score color from `theme.palette.scoreRing`. The 100-unit SVG uses a 47-unit radius and 4-unit stroke. One elapsed-time animation drives the arc, integer counter, and color together. A two-part Hermite curve advances about 85% of the score in the first 65% of the timeline, then eases continuously to the final value. Duration scales from about 535ms at 1% to 1,300ms at 100%. The stroke blends smoothly from red through yellow and light green to green around 58–63%, 73–78%, and 88–93%. These colors are decorative cues; the numeric result remains authoritative. Zero has no arc, and invalid percentages safely display zero. The final score remains available as stable screen-reader text while changing visual digits are hidden from announcements. Reduced-motion preference shows the final number, ring, and color immediately.

The quiz and flashcard dashboards share the same responsive dashboard frame, subject grid, subject-card base, and user-controlled study carousel. Feature wrappers provide their own status content; score details belong only to quiz cards, while flashcard cards may show deck counts and active decks. The carousel never auto-advances, uses labelled previous/next controls with wraparound navigation, and shows controls only when cards overflow the visible responsive layout. Subject cards use native button semantics and visible focus treatment; reduced-motion navigation jumps directly to the next item. Quiz and flashcard subject pages share the same back/header frame while keeping feature-specific lists and actions separate.

Both dashboards use the shared catalog `StatCard` component for the same label and number hierarchy. The flashcard dashboard places Completed decks, Average count, and Highest count in the responsive summary row above Continue Studying and All Subjects, without secondary descriptions. Progress read errors show unavailable values instead of zero. Keep locally stored stats visible while the subject catalog loads or recovers.

The MUI theme owns semantic feedback tones for correct, incorrect, and answer-under-review surfaces, borders, and separators. Quiz choices, the feedback header, and Browse Answers use these tokens so a palette adjustment stays consistent without changing the written correctness and review signals. The pearl surface uses `primary.light`.

Meducation uses a light, warm autumn palette with `#b9511b` as its restrained primary accent, off-white surfaces, strong type hierarchy, soft borders, 14px radius cards, and visible native MUI focus states. Correctness always combines written feedback, an icon, and color. Immediate feedback uses a compact tinted status header followed by a neutral reading surface; long explanations should have a clear heading, generous line height, and a constrained readable measure rather than a fully tinted wall of text. The shared rich-content renderer presents canonical stems and rationales as semantic Markdown, sanitized HTML, images, and KaTeX math. Inline equations align with text; display math has readable spacing and long expressions scroll within their own bounded area on narrow screens. Math fonts load locally. Tables also scroll horizontally on narrow screens, and images use meaningful alt text, lazy loading, their natural aspect ratio, and a responsive bounded width. The highlighted answer choices communicate which selection was correct or incorrect, so do not repeat answer summaries in feedback. Render optional high-yield pearls as separate callouts. A correct-answer choice receives a short, local green-circle burst, while centered celebration overlays remain reserved for streak and perfect-test events. Both effects are decorative, pointer-transparent, and non-blocking: they do not move focus, obscure controls, or shift layout. They honor `prefers-reduced-motion` by omitting moving circles while preserving written and static correctness signals. Visual formatting must not change canonical Markdown semantics.

For dashboard and subject catalogs, use MUI wave skeletons that match card and score dimensions to reserve layout space. Use restrained warm shimmer contrast and disable animation when the user prefers reduced motion. Keep headings, navigation, and locally available statistics visible while content loads. Quiz catalogs and flashcard subject catalogs share the same warm, full-width recovery banner immediately below the header, with a bordered Retry control. Their dependent cards, grid, or four subject rows retain the warm shimmer skeleton shape. Loading a selected flashcard deck uses the orange indeterminate progress bar at the shell top, as for quiz question loading, while its deck rows stay visible and its selected action is disabled. A failed deck launch uses the existing persistent bottom-right error toast; Study/Resume remains available for another try. An independent dashboard failure stays in the affected card or subject grid, with a small note and outlined Retry button. Mark loading sections `aria-busy`, give each section an accessible loading label, and keep placeholders out of the focus order. Map internal errors to learner-safe copy; technical status codes and raw exceptions belong in developer logs only. Do not show zero or empty states until that resource has loaded successfully.
